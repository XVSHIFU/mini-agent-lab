# ADR-0002：用三个深模块承载产品化能力

- 状态：Accepted
- 日期：2026-08-22

## 背景

如果继续把规则判断、文件扫描和日志拼接堆进 `Agent.executeToolCall()`，Agent Loop 会越来越难测试。综合项目需要增加能力，但不应该同步扩大调用方必须理解的接口。

## 决策

把新增复杂度放进三个深模块：

| 模块 | 接口 | 隐藏的实现 |
|---|---|---|
| `PermissionPolicy` | `evaluate()` | 字符串/对象规则、glob、优先级、五种模式、危险检测、原因码 |
| `SkillRegistry` | `list()` / `resolveInvocation()` / `execute()` / `refresh()` | 两级目录、覆盖关系、frontmatter、inline/fork、64KB 元数据读取、正文懒加载 |
| `TraceRecorder` | `record()` / `recent()` / `formatRecent()` | JSONL、序号、目录创建、脱敏、截断、失败降级 |

旧的 `checkPermission()`、`resolveSkill()` 和 `executeSkill()` 保留为兼容适配器。Agent 可以注入 `SkillRegistry` 和 `TraceRecorder`，测试与生产跨过同一条 seam。

## 影响

Agent 仍负责流程编排，但不再了解规则和日志文件细节。测试可以通过公开接口描述行为，不需要 mock 自己的内部模块。代价是多了三个需要命名和维护的模块；它们都隐藏了足够多的复杂度，删除任何一个都会让逻辑重新散落到多个调用点，因此不是空壳抽象。
